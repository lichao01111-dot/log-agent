# 第一课：领域内核与状态机

## 本课目标

把“探索 → 假设 → 验证 → 收敛”从一句描述变成可执行、可测试的程序契约。

本课刻意不接 LLM、Splunk、数据库和 Web API。领域层只接收已经发生的事件，计算新状态和下一条命令：

```text
transition(旧状态, 已发生事件) -> (新状态, 待执行命令)
```

这种设计把不可预测的外部系统留在边界外，使核心流程可以确定性重放。

## 代码导读

本章不是只有状态图，代码集中在两个文件：

| 阅读目标 | 源码 | 对应测试 |
|---|---|---|
| 阶段、预算、事实、假设、证据、结论与调查聚合 | [`domain/models.py`](../src/log_agent/domain/models.py) | [`test_domain.py`](../tests/unit/test_domain.py) |
| Event、Command、Transition 与全部状态转移 | [`domain/state_machine.py`](../src/log_agent/domain/state_machine.py) | [`test_domain.py`](../tests/unit/test_domain.py) |
| 从 `NEW` 跑到终态的完整行为 | 上述两个文件 | [`test_fake_investigation.py`](../tests/integration/test_fake_investigation.py) |

建议按下面顺序读：

1. 先读 `Phase`、`QueryBudget`、`WorkingMemory` 和 `Investigation`，理解状态里保存什么。
2. 再读 `Investigation.__post_init__()`，看终态互斥、pending operation 和证据引用如何被强制校验。
3. 然后读 `state_machine.py` 顶部的 Event/Command 类型，区分“已经发生”和“请求执行”。
4. 最后从公开函数 `transition()` 开始，沿 `_on_*` 和 `_issue_*` 函数跟踪一条 Happy Path。

关键代码可以概括为：

```python
def transition(state: Investigation, event: Event) -> Transition:
    # 先拒绝终态事件，再根据 phase + event 选择唯一处理函数。
    # 返回新状态和下一条命令；这里不执行网络 I/O。
    ...
```

`transition()` 是领域层唯一公开的状态推进入口。`_on_*` 处理已经完成的事件，`_issue_*` 创建下一条命令并在发出查询时扣减预算，`_merge_*` 更新结构化记忆。读测试时不要只看 Happy Path，还要看错误 `command_id`、越界时间窗、未知 Evidence 和终态再次接收事件为何会失败。

## 三个关键概念

1. **状态**：调查当前处于哪个阶段、已经知道什么、还剩多少查询预算。
2. **事件**：已经发生的事实，例如查询成功、假设生成完成、用户取消。
3. **命令**：下一步希望外部执行的副作用，例如执行查询或生成结论。

事件和命令不能混为一谈。`ExecuteQuery` 只是请求；只有收到匹配的 `QuerySucceeded`，状态机才承认查询已经完成。

## 状态图

```text
NEW -> TRIAGE -> HYPOTHESIZE <-> VERIFY -> CONCLUDE
                                             |  |
                                             |  +-> INCONCLUSIVE
                                             +----> COMPLETED

任一运行态 -> FAILED
任一运行态 -> CANCELLED
```

`COMPLETED` 表示找到了有有效证据支撑的根因；`INCONCLUSIVE` 表示流程正常结束但证据不足。工具故障使用 `FAILED`，不能伪装成“无结论”。

## 本课的不变量

- 事实必须引用至少一条证据。
- 被支持或被证伪的假设必须引用相应证据。
- 有结论输出必须指向一个 `SUPPORTED` 假设，且引用真实存在的证据。
- 查询预算在发出查询命令时扣减，而不是成功后扣减。
- 每次只允许一个外部操作在途；结果事件必须携带匹配的 `command_id`。
- 终态不能重新启动，也不能再接受迟到的工具结果。
- 验证结果不能改写原假设，也不能借用本次验证查询之外的新证据。
- 后续验证查询只能缩小原调查时间窗，不能扩大范围。
- 多个候选假设按顺序验证，不能只验证第一个就丢弃其余候选。

## 当前占位与后续课程

`QueryIntent` 只表达查询目的，不包含 SPL。`EvidenceRef.record_ref` 也是不透明引用。真实 SPL、job 轮询、分页、稳定行定位和认证方式必须等 Splunk MCP 契约确认后由适配器实现。

第一版 `Conclusion` 有意不包含模型自报的置信度。置信度只有在历史 incident 上完成校准后才有意义；校准前不能用它驱动状态转移或提前结束调查。
