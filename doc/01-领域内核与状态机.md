# 第一课：领域内核与状态机

## 本课目标

把“探索 → 假设 → 验证 → 收敛”从一句描述变成可执行、可测试的程序契约。

本课刻意不接 LLM、Splunk、数据库和 Web API。领域层只接收已经发生的事件，计算新状态和下一条命令：

```text
transition(旧状态, 已发生事件) -> (新状态, 待执行命令)
```

这种设计把不可预测的外部系统留在边界外，使核心流程可以确定性重放。

## 三个关键概念

1. **状态**：调查当前处于哪个阶段、已经知道什么、还剩多少查询预算。
2. **事件**：已经发生的事实，例如查询成功、假设生成完成、用户取消。
3. **命令**：下一步希望外部执行的副作用，例如执行查询或生成结论。

事件和命令不能混为一谈。`ExecuteQuery` 只是请求；只有收到匹配的 `QuerySucceeded`，状态机才承认查询已经完成。

## 状态图

```text
NEW -> TRIAGE -> HYPOTHESIZE <-> VERIFY -> CONCLUDE
                                             |  |
                                             |  +-> INCONCLUSIVE
                                             +----> COMPLETED

任一运行态 -> FAILED
任一运行态 -> CANCELLED
```

`COMPLETED` 表示找到了有有效证据支撑的根因；`INCONCLUSIVE` 表示流程正常结束但证据不足。工具故障使用 `FAILED`，不能伪装成“无结论”。

## 本课的不变量

- 事实必须引用至少一条证据。
- 被支持或被证伪的假设必须引用相应证据。
- 有结论输出必须指向一个 `SUPPORTED` 假设，且引用真实存在的证据。
- 查询预算在发出查询命令时扣减，而不是成功后扣减。
- 每次只允许一个外部操作在途；结果事件必须携带匹配的 `command_id`。
- 终态不能重新启动，也不能再接受迟到的工具结果。
- 验证结果不能改写原假设，也不能借用本次验证查询之外的新证据。
- 后续验证查询只能缩小原调查时间窗，不能扩大范围。
- 多个候选假设按顺序验证，不能只验证第一个就丢弃其余候选。

## 当前占位与后续课程

`QueryIntent` 只表达查询目的，不包含 SPL。`EvidenceRef.record_ref` 也是不透明引用。真实 SPL、job 轮询、分页、稳定行定位和认证方式必须等 Splunk MCP 契约确认后由适配器实现。

第一版 `Conclusion` 有意不包含模型自报的置信度。置信度只有在历史 incident 上完成校准后才有意义；校准前不能用它驱动状态转移或提前结束调查。
