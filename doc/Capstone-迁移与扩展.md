# Capstone：迁移与扩展

> 状态：课程收束设计。应在第 7–10 章的真实接入、评估、入口和可观测性门槛完成后实施。

Capstone 不要求再堆一层框架，而是要求你证明：哪些工程原则可以迁移，哪些设计必须随领域和风险重新推导。

## 任务一：从被动问答扩展到告警增强

当前 MVP 由工程师主动提交调查请求。告警增强可以复用：

- `Investigation` 领域模型和状态机；
- `CommandExecutor` 与 `InvestigationRunner`；
- 查询安全管线和知识投影；
- ReasoningPort、LogSearchPort 及其 Adapter；
- 证据和结论不变量。

但它不只是“换一个触发器”。无人值守入口新增了不同的风险和契约：

| 新问题 | 必须明确的设计 |
|---|---|
| 告警代表谁发起查询 | 告警来源身份到受信 `scope_ref` 的授权映射 |
| 同一告警重复投递 | 幂等键、去重窗口和恢复策略 |
| 告警风暴 | 并发、速率、查询成本和每租户配额 |
| 时间窗和预算从哪里来 | 受信策略生成，不能直接接受 webhook 自由字段 |
| 结论发往哪里 | 输出 Adapter、访问控制、脱敏和审计 |
| 是否自动采取动作 | 能力目标仍限于只读诊断，真实服务端只读保证待第 7 章验收；`INCONCLUSIVE` 与 `FAILED` 必须升级给人工 |

推荐的数据流是：

```text
已认证告警
→ 验证并规范化 AlertContext
→ 授权服务解析 scope 和预算
→ 构造 InvestigationRequest
→ 复用诊断内核
→ 输出经过策略过滤的结论
→ 人工确认或进入告警记录
```

不要把告警 payload 直接翻译成 raw index、SPL、模型 System Prompt 或任意时间范围。

### 验收练习 A

为同一个告警连续投递两次，证明：

- 不会重复消耗两份查询预算；
- 第二次能取得同一调查状态或安全返回“正在处理”；
- 告警中的伪造 scope 不会改变实际授权范围；
- inconclusive 不会被包装成已确认根因。

## 任务二：迁移到另一个诊断/调查类 Agent

选择代码故障诊断、客服工单调查或合规事件调查中的一个。迁移时先区分“原则”和“具体状态”。

### 通常可以复用的原则

- 范围和非目标先于实现；
- Event/Command 分离副作用和已发生事实；
- 外部系统通过 Port/Adapter 接入；
- 权限、预算、证据账本和终止条件由程序拥有；
- Working Memory 保存有界结构和引用，不累计完整历史；
- 模型只返回严格草稿，不能直接执行或授予权限；
- 结果评估和确定性过程评估分开；
- 安全 Trace 使用结构化 decision code，不记录敏感原文或模型私有推理。

### 必须重新设计的内容

- 状态图和每条允许的转移；
- 工具能力、身份授权和副作用边界；
- 什么算 Fact、Evidence 和“根因已被支持”；
- 领域知识 Schema 与可见性策略；
- 查询或动作预算；
- 成功、证据不足、策略拒绝和工具失败的终态；
- 评估数据、质量门槛和人在回路位置。

`Triage → Hypothesize → Verify → Conclude` 是诊断类任务的一个候选骨架，不是所有 Agent 的定律。代码评审可能更适合 `Collect → Analyze → Challenge → Report`，审批任务可能需要显式 `AwaitApproval`。迁移的目标不是保留阶段名字，而是重新证明每个状态和权限为什么存在。

### 迁移证明模板

为新 Agent 填写下面的表：

| 问题 | 你的答案 |
|---|---|
| 用户真正要完成的结果是什么 | |
| 为什么单次调用或普通 workflow 不够 | |
| 哪些步骤需要模型的动态判断 | |
| 哪些决定绝不能交给模型 | |
| 有哪些外部工具和副作用 | |
| Evidence 的结构和来源是什么 | |
| 哪些终态必须区分 | |
| 如何限制预算和循环 | |
| 如何构造可复现评估集 | |
| Trace 中什么可以记录、什么禁止记录 | |

如果无法回答其中任一项，就还没有理由复用当前架构。

## 最终答辩

Capstone 的交付物不是更多代码，而是一份迁移 ADR 和两个攻击测试：

1. 一份 ADR，说明保留、替换和删除了哪些边界，以及原因。
2. 一个权限攻击测试，证明不可信输入不能扩大工具能力。
3. 一个证据攻击测试，证明模型不能引用不存在或不可见的证据。
4. 一次评估对比，证明迁移前后或改版前后没有破坏关键过程不变量。

## Takeaway

> 可迁移的是“如何分配控制权、建立证据和验证边界”的方法，不是某个固定状态图。任何新触发方式或新领域都必须重新完成威胁分析、权限设计和评估证明。
