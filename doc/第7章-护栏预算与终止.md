# 补充专题：护栏、预算与终止（当前实现映射）

> 本文是第 1、4、6 章的复盘材料，不再作为课程主线中的第 7 章。主线第 7 章是[真实适配器与脱敏边界](07-真实适配器与脱敏边界.md)。

旧版课程把护栏集中到最后再加一个 `guardrails.py`。当前实现采用了更可靠的做法：先缩小系统能够表达的动作，再在领域状态机、查询策略、执行器和模型边界分别落实约束。这样，护栏不是一个容易绕过的外围检查，而是类型和状态转移本身的一部分。

## 1. 要防止的三类失控

| 风险 | 当前控制点 | 超限或违规后的语义 |
|---|---|---|
| 无限查询或查询成本失控 | `QueryBudget` 在命令签发时扣减预算 | 正常生成 `INCONCLUSIVE / QUERY_BUDGET_EXHAUSTED` |
| 越权查询或扩大范围 | `QueryPlan`、`ScopePolicy`、`QueryPolicyGate` | fail closed，转为 `FAILED / OPERATION_FAILED` |
| 模型伪造证据或越权控制流程 | `CommandExecutor` 与状态机不变量 | 拒绝协议结果，转为安全失败 |
| 外部调用卡住 | Executor 的搜索/推理 timeout | 取消端口调用并返回安全错误事件 |
| 用户主动停止 | `CancelRequested` | `CANCELLED / USER_CANCELLED` |
| 上下文和输出过大 | `ProjectionBudget`、结构化输出上限 | 投影截断或安全拒绝，不继续扩大披露 |

这里最重要的区分是：

- **预算耗尽但系统正常**是 `INCONCLUSIVE`，不是异常；
- **查询策略、外部能力或协议失败**是 `FAILED`；
- **用户取消**是 `CANCELLED`；
- 只有证据支持根因时才能进入 `COMPLETED`。

不要把这些情况都压成一句“运行失败”，否则评估、告警和人工接管都会失去依据。

## 2. 为什么不接收模型生成的 raw SPL

旧版方案先让模型生成任意 SPL，再解析管道并检查命令白名单。它有两个问题：

1. 完整解析一种查询语言本身就是高风险工作；字符串分割无法可靠识别子搜索、宏、转义和语义组合。
2. 即使命令名都在白名单内，索引、时间范围、结果规模和字符串组合仍可能越权。

当前查询路径从能力上消除了这个入口：

```text
模型/状态机给出 QueryIntent
        ↓
QueryPlanCompiler 选择固定 template_id 与 operation
        ↓
QueryPolicyGate 对 scope、来源、时间范围、模板和上限授权
        ↓
AuthorizedQueryPlan
        ↓
真实 Adapter 才能在受信任代码中渲染 provider 请求
```

公开的 `QueryPlan` 不含 `raw_spl`，模型只能提供受限的 `QueryLiteral`。因此安全策略采用的是“允许哪些结构”，而不是“猜测哪些字符串危险”。真实 Splunk Adapter 仍需使用固定 Renderer，并在服务端 RBAC 下以只读身份运行；这部分是主线第 7 章的接入门槛。

## 3. 预算为什么在签发命令时扣减

`QueryBudget` 同时记录总查询额度与 Verify 查询额度：

```python
QueryBudget(
    max_total_queries=4,
    max_verify_queries=2,
)
```

状态机在创建 `ExecuteQuery` 命令时调用 `issue(kind)`。这比“查询成功后再计数”更安全，因为超时、失败和取消的外部请求同样消耗过系统资源，也不能通过反复失败逃避预算。

当无法再签发查询时，状态机不会抛出一个由循环外层随意解释的异常，而是签发 `GenerateConclusion`，要求得到：

```text
ConclusionOutcome.INCONCLUSIVE
TerminationReason.QUERY_BUDGET_EXHAUSTED
```

模型可以帮助措辞，但不能把该结果改写为“已找到根因”。Executor 会检查返回的 outcome、termination reason 和证据引用是否与待执行命令一致。

## 4. 终止不是“置信度超过阈值”

当前领域模型没有 `confidence` 字段。这是有意为之：一个模型自报的 0.93 并不能证明根因成立，也不适合直接控制高风险状态转移。

收敛由可验证条件决定：

- 根因假设必须处于 `SUPPORTED`；
- 结论必须引用当前 Working Memory 中已经存在的 Evidence；
- 结论证据必须是该根因假设的 supporting evidence；
- outcome 和 termination reason 必须与状态机签发的命令相同。

没有满足这些条件时，系统应返回带明确原因的 `INCONCLUSIVE`，而不是制造一个“低置信度根因”。概率分数未来可以作为评估特征，但不能替代证据不变量。

## 5. 当前 Runner 为什么不需要手写 `while rounds < N`

`InvestigationRunner` 仍然有循环，但循环只负责搬运状态机产生的单个 Command：

```text
transition(state, event) → Command
CommandExecutor.execute(state, command) → Event
transition(state, event) → ...
```

Runner 不判断“下一阶段是什么”，也不自行判断是否收敛。终止由领域转移决定；查询循环最终受 `QueryBudget` 限制。这样不会出现 Runner、Guardrail 和模型各自维护一套轮数规则的问题。

需要注意，真实部署还应补充整次调查的 wall-clock deadline、模型 token/cost budget，以及可恢复任务的最大重试次数。这些属于装配与运行策略，应在第 7、9 章的外部边界中实现，而不是让模型决定。

## 6. 护栏放在哪里

一个实用判断方法是看“谁拥有该事实”：

| 约束 | 应放的位置 | 原因 |
|---|---|---|
| 合法状态和终态 | Domain state machine | 与任何 provider 无关 |
| 查询次数 | Domain `QueryBudget` | 是调查级业务规则 |
| scope、时间、模板、结果上限 | Application query policy | 需要受信任配置授权 |
| provider 请求格式、分页和轮询 | Splunk Adapter | 取决于真实 wire contract |
| timeout 与外部错误翻译 | CommandExecutor / Adapter | 属于能力调用边界 |
| 字段脱敏与最小披露 | Sanitizer + model Adapter | 属于数据外发边界 |
| RBAC、并发和租户限流 | 入口与基础设施 | 依赖调用身份和部署环境 |

因此，“把所有护栏放进一个类”并不是目标。目标是每条规则只有一个权威拥有者，且所有执行路径都无法绕过它。

## 7. 用测试证明，而不是靠阅读代码安心

建议按风险编写反例测试：

1. 总预算或 Verify 预算耗尽后，断言搜索端口没有被再次调用，终态为 `INCONCLUSIVE`。
2. 未知 `scope_ref`、越界时间窗、未知模板或超大 result limit 必须在 Adapter 前失败。
3. 返回未知 Evidence ID、篡改 Hypothesis 文本或改变 conclusion outcome 时，必须得到协议错误。
4. 搜索与推理 timeout 后，底层 coroutine 应收到取消，用户只看到安全错误消息。
5. `CancelRequested` 后状态立即终止，任何后续 Event 都应被拒绝。
6. Projection 超过字符或实体预算时，只能丢弃完整实体或拒绝，不能输出半个 JSON 对象。

对应的现有测试主要位于：

- `tests/unit/domain/test_state_machine.py`
- `tests/unit/application/test_query_security.py`
- `tests/unit/application/test_executor.py`
- `tests/unit/application/test_knowledge_projection.py`
- `tests/integration/test_fake_investigation.py`

## 8. 练习

### 练习 A：解释一次预算耗尽

从集成测试中找到 `QueryBudget` 的配置，画出每次 `ExecuteQuery` 在何时消耗总预算、何时消耗 Verify 预算。回答：为什么失败查询也不应返还预算？

### 练习 B：设计一条攻击测试

尝试让 Verify 目标携带布尔操作符、让查询时间超出 Request，或让模型引用未出现过的 Evidence ID。先写出你预期的安全终态和“外部端口是否被调用”，再运行测试验证。

### 练习 C：补全生产预算

在不修改模型权限的前提下，为生产装配设计三类额外预算：整次调查 deadline、模型 token/cost、外部查询并发。标出它们各自的拥有者、扣减时机和终止语义。

## Takeaway

可靠的护栏不是在自由行为外面补几个字符串检查，而是让危险行为无法通过公共契约表达。程序拥有权限、预算、证据和终止；模型只能在这些边界内提供语义草稿。
