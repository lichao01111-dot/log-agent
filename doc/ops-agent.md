先说一句可能不中听的:你现在最缺的不是模块,是把已有的东西演完整。三块能力 + 关注点系统本身已经够撑一个奖了,再堆功能的边际收益远低于把关注点那条链路打磨到不翻车。下面这些是在"如果时间还有富余"的前提下说的,按性价比排序。

1. 反事实回放(最推荐)

拿一次真实的历史故障,固定时间窗喂给 agent,让它在台上重跑一遍,和当时人工排查的时间线并排放:人用了 47 分钟定位,agent 用了 90 秒,结论一致。

这是全场唯一能让评委相信"它真的有用"而不只是"它看起来聪明"的东西。而且它不是新功能——只是给已有能力加一个时间窗参数和一个对比视图,工作量很小。同时它顺手解决了你的评估问题:回放集攒起来了,后面改 prompt 才有依据。

2. 置信度与不确定性表达

让 agent 明确说"我不确定"和"我需要更多数据"。比如结论分三档:证据充分 / 存在合理假设但未验证 / 数据不足无法判断。

反直觉的地方在于:一个会说"我查不出来"的系统,比一个每次都给答案的系统更可信。懂行的评委看到这个会立刻加分,因为这说明你想过幻觉问题。实现上就是在 Finding 里加一个字段和相应的 prompt 约束。

3. 假设树的可视化

error 调查那条链路,把它内部的假设 → 验证 → 排除过程画成一棵树展示出来。"怀疑是数据库 → 查了,排除;怀疑是新版本 → 查了,命中"。

评委看 agent 输出一段结论,感受是"它说了句话";看它排除了三个假设才收敛到第四个,感受是"它在推理"。同样是零新增能力,纯展示层。

4. 一句话时间旅行

输入"两小时前发生了什么",agent 自动定位那个时间窗并给出当时的态势报告。这个交互本身很有画面感,而且实现只是给态势感知加个时间参数 + 一层自然语言时间解析。

我建议不要加的:自动修复动作。听起来最炫,但风险收益比最差——评委会立刻追问权限、回滚、误判代价,你一旦答不周全,前面积累的可信度会瞬间掉光。让它停在"给出建议动作并标注是否需要审批"是更成熟的姿态,反而显得你想清楚了边界。

如果只能挑一个,选反事实回放。它同时解决了说服力和评估两件事,而且是四个里工作量最小的。
