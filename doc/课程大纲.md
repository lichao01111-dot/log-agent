# 用一个真实案例讲透可靠 Agent 工程

> 一门以日志诊断 Agent 为主线、以当前仓库实现为事实源的工程课程。

课程唯一入口见 [教学文档 README](README.md)。

## 这门课教什么

日志诊断只是案例，真正学习的是如何把概率性的模型能力放进一个可验证的软件系统：

- 判断一个需求应该使用单次模型调用、workflow，还是 Agent；
- 把开放任务拆成显式状态、事件、命令和终止条件；
- 用 Port/Adapter 隔离模型与工具 SDK；
- 让权限、预算、状态和证据归程序控制；
- 用领域知识帮助推理，但不让知识配置授予执行权限；
- 用测试、评估和安全 Trace 让系统可以回归和迭代。

目标受众是会 Python、有基本 API 概念、但没有系统开发过 Agent 的工程师。

## 本课程中的 Agent 定位

```text
确定性控制面：状态机 / Policy / Budget / Evidence / Termination
概率性语义面：Hypothesis / Verdict draft / Summary
外部能力面：Splunk MCP / Model Provider
```

模型不会直接调用 Splunk，也不会决定状态转移。它在每个阶段提交一个受限草稿，应用校验后再生成领域对象。这保留了动态推理能力，同时避免自由 ReAct loop 获得不必要的权限。

## 可靠性递进

| 阶段 | 章节 | 要解决的问题 |
|---|---|---|
| 可控 | 1–3 | 流程、状态、外部调用和失败语义能否确定性测试 |
| 安全 | 4–6 | 查询、知识、模型上下文和证据能否越权或伪造 |
| 接现实 | 7 | Fake 契约如何安全映射到真实 MCP、模型和生产数据 |
| 可判断 | 8 | 如何证明改模型、Prompt、知识或策略后没有退化 |
| 可运行 | 9 | 如何装配依赖、建立安全入口并处理恢复与幂等 |
| 可维护 | 10 | 如何安全观测、回放和形成评估反馈闭环 |

## 十章结构

| 章 | 主题 | 通用概念 | 日志 Agent 落地 |
|---|---|---|---|
| 1 | 领域内核与状态机 | 控制权、Event/Command、不变量 | Triage → Hypothesize → Verify → Conclude |
| 2 | 端口与适配器 | 依赖倒置、外部协议边界 | LogSearchPort 与 ReasoningPort |
| 3 | Executor 与 Fake 闭环 | 副作用翻译、错误/超时/取消 | 无网络跑通完整调查 |
| 4 | 安全查询管线 | 正向 allowlist、预算、fail closed | SPL-free QueryPlan 与 ScopePolicy |
| 5 | 领域知识配置 | 知识/权限信任域分离 | 严格 JSON KnowledgeSnapshot |
| 6 | 知识投影与结构化推理 | 最小披露、结构化草稿、证据接地 | 分阶段 Projection 与临时 Evidence alias |
| 7 | 真实适配器与脱敏 | wire contract、normalization、redaction | Splunk MCP 与 Model Provider 接入门槛 |
| 8 | 评估与回归 | outcome/process 分离、可复现性 | 历史 incident 与安全攻击集 |
| 9 | 装配与安全入口 | Composition Root、身份授权、恢复 | 复用现有 Runner，建立用户入口 |
| 10 | 可观测性与迭代 | 安全 Trace、指标、回放、发布门 | 用结构化事件反哺知识与 Prompt |

## 当前完成度

- 第 1–5 章：已有对应实现和测试。
- 第 6 章：provider-neutral 结构化推理与 Fake 模型闭环已实现；生产 Sanitizer 和真实模型未接。
- 第 7 章：接入契约与验收门槛，受真实 Splunk MCP、RBAC 和生产数据分类阻塞。
- 第 8 章：仓库已有完整的确定性测试套件；历史 incident 数据集和评估 runner 尚未实现。
- 第 9 章：`CommandExecutor + InvestigationRunner` 已实现；安全 API/CLI、持久化和恢复尚未实现。
- 第 10 章：已有本地 `ModelTraceContext`，完整 Trace sink、指标和回放尚未实现。

因此目前不能宣称“已经得到一个生产可用的 Splunk Agent”。当前准确交付物是：

> 一个经过严格契约测试的日志诊断 Agent 内核，以及连接真实工具和模型之前必须满足的工程门槛。
